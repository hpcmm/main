# HPC-MM website — colleague-friendly edition

## First installation
Unzip the download and upload ALL files into the same GitHub folder as your existing index.html. Replace matching files. Keep the current Pages settings. Relative links work at both a root domain and /hpcmm-website/.

## Everyday updates — no HTML editing
1. Open your website and select **Edit website content** in the footer (or open editor.html).
2. Use the sections to edit the group introduction, research, publications, members, software, news, and contact details.
3. For each member, enter their biography and interests, and tick the papers that belong to them. Adding members automatically creates a working profile link; no extra HTML file is needed.
4. In **Cover & group photos**, choose the two images separately. Add an accessibility description and caption/credit for each. Both remain placeholders until supplied. PNG, JPG and WebP up to 5 MB per image are accepted. Photos are preserved at their original proportions, without cropping faces.
5. Select **Preview draft**. Homepage and member previews use your current draft.
6. Select **Download updated content.js**. If your browser adds a number to the filename, rename it to exactly content.js.
7. In GitHub, upload that file to the same folder as index.html, replace the existing content.js, and commit. Wait for Pages to deploy and refresh the website.

Only content.js needs uploading for routine content and photo updates. The editor embeds the photos in that file so colleagues do not need to manage image paths. For faster loading, resize large photographs before selecting them (roughly 1600–2000 pixels wide is ample for most uses).

## Drafts and collaboration
The editor does not publish automatically and has no GitHub credentials. Anyone can try the form, but publishing requires repository write access. Edits stay in the tab until downloaded; they are not automatically saved. A downloaded file can be restored using **Load a saved content file**. Refresh the editor before starting to get the latest published content. Coordinate edits: uploading an old content file replaces newer content rather than merging it.

## Placeholder labels
Every example member, paper, research area, news item and software entry has a checkbox marking it as example content. Uncheck it only once you have supplied real information. The overall draft banner disappears once no example entries remain. Also replace/remove the group draft note and placeholder affiliation text.

## Files
- content.js: all editable content and photos; generated by the visual editor.
- editor.html, editor.js, editor.css: visual editor, validation, import, preview and download.
- index.html, site.js, script.js, styles.css: website structure, rendering and interactions.
- member.html: profiles for all members, selected by their permanent identifier.
- Original named profile HTML pages: retained so older profile links continue working.
- favicon.svg: provisional group icon.

No dependencies or build process. JavaScript is required for content rendering and the editor. Open editor.html locally after extracting the ZIP, or use the hosted editor. GitHub Pages is not changed by simply opening or using the form.
